OFAC List Sync Glossary Part 1

Core terms for keeping local screening data current with OFAC's sanctions lists as they change.

TL;DR

TL;DR: List sync is the process of refreshing local screening data to match OFAC's current lists. Screening against a stale list misses newly listed parties and creates a false sense of compliance.

What list sync is

OFAC updates its sanctions data frequently, adding and removing names and wallet addresses as designations change. List sync copies those changes into the local screening system so every check runs against current data. A sync process must capture the full SDN List plus OFAC's crypto wallet addresses. Gaps between updates create a window where a newly listed party is not yet blocked, which is exactly when a stale system can approve a prohibited payment.

Why it matters for agent payments

An agent payment engine that syncs weekly, or not at all, will miss designations made in between. Because OFAC enforces strict liability, a payment to a party listed minutes before the transaction is still a violation. sanctionsai.dev syncs its live data hourly: 947 OFAC-listed crypto wallets, 19,218 SDN names, and 16 jurisdictions. That freshness is what lets the API return a reliable clean or flagged result in one HTTP call under 100 ms.

Terms covered in Part 1

  • Sync interval: how often local data is refreshed from source.
  • Designation: the act of adding a party to a sanctions list.
  • Stale list: screening data that no longer matches OFAC's current lists.
